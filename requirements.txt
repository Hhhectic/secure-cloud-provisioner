# Everything needed to run the whole tool, both clouds:
#
#     pip install -r requirements.txt
#
# The split between this file and backend/requirements.txt is historical. This
# one belonged to the root Azure application, which has been deleted, and it is
# now the only declaration of the Azure SDK in the repository. Rather than merge
# the two files and lose the provenance comments below, this one pulls the other
# in. Installing either file on its own used to produce a checkout that could
# run only half the tool, and said so as a 503 on one tab.
#
# CI installs backend/requirements.txt directly: the offline suite needs boto3,
# moto and pytest, and never reaches an Azure module.
-r backend/requirements.txt

# --- Azure ----------------------------------------------------------------
#
# The Azure half degrades the same way the AWS half does without boto3.
# api/registry.py imports every provider module at startup, and a missing SDK
# costs one tab rather than the whole page - see az/common.py.
azure-identity==1.15.0
azure-mgmt-resource==26.0.0
azure-mgmt-storage==21.0.0
# az/nsg.py and az/common.py:network_client have needed this since the merge
# and it was never listed, so `pip install -r requirements.txt` produced a
# checkout where importing azure_crud.py failed outright. A floor rather than a
# pin because nothing here has resolved it against a real install yet; pin it
# once the Azure half has run against a subscription.
azure-mgmt-network>=25.0.0
# az/keyvault.py. Resolved against a real install at 14.0.1.
azure-mgmt-keyvault>=14.0.0
# az/vm.py, which arrived with virtual machine provisioning and was listed
# nowhere at all - not here and not in backend/requirements.txt. A checkout
# that installed both files still could not open the Azure virtual machine tab,
# and said so as a 503 naming a module rather than as an import error, which is
# the lazy-import design working: the page starts, one type is unavailable.
# Resolved against a real install at 38.2.0.
azure-mgmt-compute>=38.0.0
# az/monitor.py, which arrived with the azure-monitor type. Listed here at the
# same time as the code that needs it, which is the third attempt at a habit -
# azure-mgmt-network and azure-mgmt-compute were both needed for weeks while
# appearing in no requirements file, and each produced a checkout that
# installed cleanly and then answered 503 on one tab.
#
# Resolved against a real install at 7.0.0. Note that 7.0.0 ships no
# diagnostic-settings operation group at all, which is why az/monitor.py covers
# activity log alerts and says plainly that it does not cover the rest.
azure-mgmt-monitor>=7.0.0
